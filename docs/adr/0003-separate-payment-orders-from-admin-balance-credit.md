# ADR 0003：支付充值与管理员补款分离

## 状态

已接受，2026-08-23。

## 背景

系统按供应商确认的 Token 用量实时扣减余额。用户未来需要通过真实支付渠道充值，管理员也需要在支付异常或售后场景中人工补款。如果两种操作都写成普通“充值”，收入、渠道对账和责任追踪会失真。

## 决策

1. 用户充值建立 `recharge_orders`，支付渠道通知写入幂等 `payment_events`；只有已确认支付才能生成 `recharge` 余额流水。
2. 管理员补款不创建支付订单，写入 `adjustment` 流水，并保存操作者、原因和补款前后余额。
3. 管理员补款的余额更新、资金流水和 `admin_audit_events` 必须在同一数据库事务提交。
4. 资金操作使用幂等键和唯一约束，重复请求只返回原结果，不重复到账。
5. 余额流水、充值订单和支付事件是追加式财务事实，不使用 Token/工具记录的五页自动删除规则。

## 结果

- 管理员可为自己或任意账号补款，被禁用账号也可先补款，但补款不会自动恢复账号状态。
- 开发环境模拟充值经过同一订单和支付事件链路；生产环境继续禁用用户模拟入口。
- 接入真实渠道时仍需实现签名校验、异步 Webhook、退款状态机和渠道对账。
