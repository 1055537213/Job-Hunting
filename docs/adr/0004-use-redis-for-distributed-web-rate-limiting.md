# ADR 0004：使用 Redis 实现分布式 Web 限流

## 状态

已接受，2026-08-23。

## 背景

进程内滑动窗口只能保护一个 Web 进程。增加 Web 副本后，每个进程都会重新获得完整额度，
认证暴力尝试、模型调用和大文件分析的实际并发流量会随副本数放大。

## 决策

1. Docker 和生产 Web 使用 Redis 原子滑动窗口，Redis 数据库 1 与 Celery broker 的数据库 0 分开。
2. 有效登录态按 `account_id` 共享额度，未登录或无效登录态按直接连接的客户端 IP 限流；Redis 键只保存标识哈希。
   生产 Web 仅在 Compose 内网开放，并信任 Caddy 重写后的客户端地址；本地直连环境不信任任意转发头。
3. 请求按认证、模型调用、上传分析、管理端、普通写入和普通读取分组，各组使用独立额度。
4. Redis 不可用时，认证、模型、上传、管理端和普通写入返回 `503`；普通读取临时放行，并记录 Prometheus 故障计数。
5. 本机直接运行和单元测试默认保留内存实现；生产环境必须配置 Redis 后端，否则拒绝启动。
6. 请求指标继续由每个 Web 实例独立暴露，未来由 Prometheus 按实例采集和聚合，不把每次请求指标写入 Redis。

## 结果

- 多个 Web 进程不能通过各自的内存计数重复获得额度。
- Redis 窗口只保存短期保护状态，不成为账号、任务或计费事实源，也不进入业务备份。
- 本决策只完成共享限流；截图/模型共享并发租约、Agent 短期状态和多副本流量验证仍需后续实施。
