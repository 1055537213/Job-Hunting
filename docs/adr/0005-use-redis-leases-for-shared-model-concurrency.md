# ADR 0005：使用 Redis 租约控制共享模型并发

## 状态

已接受，2026-08-23。

## 背景

请求频率限制只能控制单位时间内的请求数量，不能限制同一时刻正在执行的模型调用和
截图解析数量。Web 或 Worker 增加副本后，进程内信号量会按副本重复分配额度，可能同时
放大供应商并发、内存占用和上游故障影响。

## 决策

1. Docker 和生产环境使用 Redis 数据库 1 保存短期并发租约，与 Celery broker 的数据库 0 分开。
2. Chat、Embedding 和 Rerank 共享 `model` 资源的全局额度与单账号额度；截图上传另有
   `screenshot` 资源额度，并在读取图片正文前占位。
3. LangChain ChatModel 通过回调在真实供应商调用开始时获取租约，在成功或异常结束时释放；
   Embedding 和 Rerank 适配器只包裹真实 HTTP 调用，不把数据库和工具执行时间计入模型并发。
4. Redis 使用 Lua 脚本原子完成过期清理、全局/账号两级判断和占位。Redis 键只保存账号 ID
   的 SHA-256 摘要，不保存邮箱、提示词、截图或模型回复。
5. 租约默认 15 分钟自动过期，与当前后台任务硬超时一致；进程崩溃或网络中断导致释放失败时，
   Redis 会自动回收名额。正常释放幂等，释放失败不覆盖已经完成的业务结果。
6. 额度已满返回 `429` 和 `Retry-After`，共享后端不可用返回 `503`。开发和测试可使用进程内
   实现；生产环境必须启用 Redis，否则应用拒绝启动。

## 结果

- Web 和 Worker 副本不能各自重复获得完整模型或截图并发额度。
- 单个账号不能占满全部模型容量，其他账号仍可在全局额度内继续使用。
- Redis 仅保存短期保护状态，不成为任务、账号、RAG 或计费事实源，也不进入业务备份。
- 本决策不替代请求频率限制；频率窗口与同时执行数量分别控制不同风险。
- `scripts/validate_multi_replica.ps1` 已覆盖两个 Web 副本的登录/限流探针、Prometheus
  服务发现，以及跨副本共享模型租约探针。
- 后续仍需完成 Prometheus 多实例长期采集、供应商熔断和 Agent 短期状态共享。
