# 统一知识文件资产与版本管理

## 目标

`knowledge_assets` 表示用户眼中的一份逻辑资料，`knowledge_asset_versions` 表示这份资料
不可变的文件版本。业务模块不再各自重新定义文件身份、哈希、来源和修订号，为后续接入
工业 PDF、图片、表格和多模态检索提供统一入口。

## 数据边界

- `knowledge_assets` 保存账号、候选人、资产类型、标题、生命周期和低敏业务元数据。
- `knowledge_asset_versions` 保存版本号、当前版标志、对象存储键、SHA-256、媒体类型、
  来源、修订标签、扫描状态和处理状态。
- 文件字节仍只保存在 MinIO/S3-compatible 对象存储；数据库不保存原件正文或二进制。
- 每个资产只能有一个当前版本；新版本在事务中追加，旧版本不会被覆盖。
- 同一资产内相同 SHA-256 不会重复建版，存储键在全库保持唯一。
- 资产和版本读取必须经过 `account_id` 所有权过滤，候选人资料还受 `candidate_id` 约束。

## 当前接入范围

原始简历上传是第一个适配器。创建 `resume_artifacts` 时，同一事务会创建统一资产和首版；
扫描通过、隔离、OCR 完成或失败时，两边状态同步。删除最后一个引用该资产的简历记录时，
资产及版本通过外键级联删除。迁移 `20260825_0012` 会为已有原始简历原地补登记资产关系，
不会移动或复制对象存储中的文件。由于旧数据没有可靠的“属于同一逻辑资料”标记，迁移不会
根据文件名猜测版本关系，而是把每份历史原件登记为一项资产的第 1 版。

GitHub 项目是第二个适配器。Worker 先把默认分支解析成 commit SHA，再下载不可变 ZIP 快照；
快照通过扫描后登记为 `project_archive` 资产，`project_archive_imports` 保存处理状态和项目卡片
关联，`project_archive_files` 保存内部路径、文件类型、摘要、解析方式和 `long_text_id`。同一
commit 重复执行会复用已有结果，新的 commit 以新内容版本导入，不再只按仓库 URL 判重。
来源修订和业务项目卡分开建模：不同快照如果提取出的可确认内容一致，可以关联同一项目卡；
删除该卡时会清理其全部快照、文件清单、对象版本和派生证据。

本地目录是第三个适配器。浏览器得到用户明确授权后递归枚举目录，先过滤 `.env`、私钥、
令牌、证书、依赖目录和构建产物，再逐文件计算 SHA-256。`project_collection_sessions` 保存
清单身份和采集进度，`project_collection_files` 保存后端选择结果、客户端/服务端双哈希、
提取方式和长文本关系。后端只请求支持且位于配额内的文件，每批最多传 5 个；成功解析后
不保存用户电脑中的文件原件；普通文件只保存提取结果和来源定位，图片与被选中的 PDF 页会
额外保存去 EXIF、受尺寸约束并重编码的视觉派生副本。
同一清单中断后会保留已分析文件并只重新请求剩余文件；用户也可以取消未完成采集，取消会
同步撤销尚未执行的索引任务并清理已经产生的文本、视觉对象和向量来源。

当前解析覆盖文本/代码、PDF 文本页及缺字页 OCR、图片 OCR、CSV/XLSX 工作表、DOCX/PPTX
和文本型 SVG/DXF/STEP/IGES。图片与有限复杂 PDF 页面还会通过当前多模态聊天模型生成页级
视觉证据；模型响应必须与请求 `source_id` 对齐，并经过置信度、字段长度和 JSON 结构校验。
视觉证据同时保存为可检索文字和结构化元数据，参数元数据保留名称、原始值、单位、公差及适用
对象；失败时本地文本/OCR 继续入库，并把文件标为待补充。`visual_knowledge_items` 将安全视觉副本
关联到账号、候选人、项目文件、`long_text_id`、图片或 PDF 页来源和对象存储键。配置
`native_multimodal` Embedding 后，独立 `visual_index` Worker 任务读取并校验对象大小与 SHA-256，
生成图片向量；重复任务按视觉项 ID 覆盖写入，不产生第二份结果。查询使用同一模型的文本向量，
合并 `rag_chunks` 与视觉向量结果，并继续执行账号、候选人、模型身份和维度隔离。前两项视觉
命中会重新读取并校验安全原图，再由多模态聊天模型针对当前查询复核可见证据；复核失败时保留
原有索引摘要，不阻断文字和视觉召回结果。

项目卡片只汇总线索，仍需候选人确认。删除项目卡片或整个候选人档案时，GitHub 快照、本地文件
证据、视觉派生对象、文件清单和 pgvector 向量沿同一生命周期清理。

工作台不新增通用知识文件页面。现有“项目导入”面板仍只有 GitHub 链接和本地目录两种来源。

## 后续顺序

1. 对工业 PDF 建立章节、表格、图片、图注和坐标元素模型，在现有页级视觉证据上增加区域定位。
2. 生成父子 Chunk，并在子元素命中后展开表头、图注、正文和页面上下文。
3. 将现有单位/公差结构化参数接入关键词与数值范围索引，并补来源坐标。
4. 接入 DWG 等二进制工程格式的受控解析器。
5. 增加视觉区域裁剪、冲突证据分组和人工核验状态。
